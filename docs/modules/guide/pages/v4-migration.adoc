= Migrating to Valentus 4
:description: Valentus 4 splits layout from paint on the --cs-* contract and moves light/dark mode to antora-ui-chassis.

Valentus 4 is three layers:

[cols="1,2,2"]
|===
| Layer | What | Where

| Mechanism
| Light/dark switching, persistence, system preference, the toggle (`@antora-supplemental/light-dark-mode`); the `--cs-*` contract, live paint and the picker page (`@antora-supplemental/color-scheme`, registered by light-dark-mode)
| antora-ui-chassis

| Layout
| Partials, helpers, JS, layout CSS; reads `--cs-*`
| `packages/valentus-layout/supplemental-ui` (this repo)

| Paint
| Token values (`:root` / `html.dark-theme`) and content colors
| Valentus Paint, `paint/` (this repo); or any `--cs-*` paint such as `@antora-supplemental/default-paint`
|===

== Release bundle users

`ui-bundle.zip` still contains layout plus Valentus Paint, so the site looks the same.
Add the chassis extension (required since 4.0.0):

[source,yaml]
----
antora:
  extensions:
    - require: "@antora-supplemental/light-dark-mode"
      toggle: placed
----

and pin it in `package.json` devDependencies:

[source,json]
----
"@antora-supplemental/light-dark-mode": "github:antora-supplemental/antora-ui-chassis#light-dark-mode-v0.1.0&path:packages/light-dark-mode"
----

The release also ships `valentus-layout-bundle.zip` (layout only). Use it with a paint extension.

If you tried a 4.0 pre-release with `- require: "@antora-supplemental/color-scheme"`, replace it with `@antora-supplemental/light-dark-mode`. light-dark-mode registers color-scheme itself; move any `live_paint` block under `color_scheme:`. The runtime API is `LightDarkMode.mode/isDark/set/toggle/subscribe` (was `ColorScheme.*` for light/dark).

== Toggle designs

Valentus Layout supports both chassis toggle designs:

[cols="1,2,2"]
|===
| `toggle_placement` | Look | Partial

| `navbar` (default)
| Sun/moon icon button in the top bar, same size as the other header icon buttons
| `light-dark-toggle.hbs` (Valentus), rendered by `{{> light-dark-navbar-slot}}` in `header-content.hbs`

| `footer`
| Labeled Light / Dark / Auto switch in the footer
| `{{> light-dark-footer-slot}}` in `footer-content.hbs`
|===

[source,yaml]
----
antora:
  extensions:
    - require: "@antora-supplemental/light-dark-mode"
      toggle: placed
      toggle_placement: footer
----

Override order for these partials is site (`supplemental_files`), then theme (Valentus), then chassis default. Hub overrides of `header-content.hbs` or `footer-content.hbs` should keep the slot partial calls.

== Git overlay users

* `supplemental_files: .../valentus-theme/supplemental-ui` becomes `.../valentus-theme/packages/valentus-layout/supplemental-ui`.
* Add the paint after light-dark-mode: `- require: .../valentus-theme/paint/lib/index.js` (Valentus look) or `@antora-supplemental/default-paint`.

== Removed and renamed

* `css/site-paint.css` is gone. Its colors are in `paint/css/valentus-paint.css`; its layout rules (VCS repo link, float groups, cards) are in `css/valentus-chrome.css`.
* Hex colors in `site-doc-layout.css`, `site-visual.css`, `site-read-width.css`, `site-font-size.css` and `site-themed-svg.css` now read tokens. The highlight.js palette and themed-SVG tokens moved to the paint.
* `head-meta.hbs` has `{{!-- color-scheme:paint-slot --}}` where `site-paint.css` was linked. *Hub overrides of `head-meta.hbs`*: replace the `site-paint.css` link with that marker plus `<link rel="stylesheet" href="{{{uiRootPath}}}/css/valentus-chrome.css">`.

== Token contract

Read colors as `var(--cs-name, system-fallback)`. Paints set, for light (`:root`) and dark (`html.dark-theme`):

* core: `--cs-canvas`, `--cs-elevated`, `--cs-ink`, `--cs-ink-muted`, `--cs-border`, `--cs-accent`
* accents: `--cs-accent-hover`, `--cs-accent-soft`, `--cs-hover`
* code: `--cs-code-bg`, `--cs-code-fg`
* callouts: `--cs-admonition-note`, `-tip`, `-important`, `-warning`, `-caution`

The six core tokens are also set as `--valentus-canvas`, `-elevated`, `-ink`, `-ink-muted`, `-border`, `-accent`. Extensions such as antora-search-chat and antora-diagram-engines read those names; they are part of the contract, not deprecated.

Brand overlays that re-tint Valentus: override `--cs-*` (both schemes) instead of `--valentus-*`.

== Writing a paint

A paint styles only shared hooks: token blocks, Default UI chrome, Asciidoctor content, highlight.js and the chassis toggle. Check it with the chassis validator:

[source,console]
----
node node_modules/@antora-supplemental/color-scheme/scripts/validate-paint.mjs my-paint.css --strict
----

Layout-specific classes must be declared (`--extra=.my-layout-`), as Valentus Paint does for `.valentus-`.

== Live paint previews

Register Valentus Paint as a live paint (color-scheme 0.3.0+, through light-dark-mode) to preview it on other layouts. With more than two schemes the chassis also builds a picker page, `_/color-schemes.html`, linked from the footer:

[source,yaml]
----
    - require: "@antora-supplemental/light-dark-mode"
      color_scheme:
        live_paint:
          enabled: true
          paints:
            valentus:
              href: css/valentus-paint.css
              slots: [light, dark]
----

For cross-site iframes, pass `?paint=valentus` in the iframe `src`; third-party cookies are often blocked.
