= antora-search-chat

Valentus Antora extension that **wraps** https://gitlab.com/antora/antora-lunr-extension[`@antora/lunr-extension`] with a Search / Ask omnibox — not a fork of lunr.

Status:: Phase 1 scaffold (stub UI + pluggable backend config). Product target is one field (*Search or Ask*); Ask is explicit (not AI-on-every-keystroke). No production LLM/RAG yet.

== Quick start

Register **after** lunr in the playbook:

[source,yaml]
----
antora:
  extensions:
    - require: "@antora/lunr-extension"
      index_latest_only: true
      index_by_heading: true
      snippet_length: 200
    - require: ./packages/antora-search-chat
      # Optional — see ARCHITECTURE.adoc
      # ask_enabled: true                 # force live "or Ask" (even without backend)
      # backend_url: https://search-api.example.com/v1/ask   # also enables Ask; no API keys here
      # default_mode: search
      # local_assist: false
----

The extension injects UI into the left-nav search slot (`.adt-nav-search` / `#search-input`) so it coexists with layout work that moved search above the nav tree.

== Placeholder UX (*Search or Ask*)

Native `<input placeholder>` cannot style part of the string. The compound control uses a **fake placeholder overlay**:

* Ask **on** (`ask_enabled: true`, or `backend_url` / `local_assist` set) — muted *Search or Ask*.
* Ask **off** — same phrase, but *or Ask* is greyed + line-through (`.adt-search-ph-ask.is-disabled`).
* Overlay hides when the field is focused or non-empty.

Markup shape:: `Search <span class="adt-search-ph-ask …">or Ask</span>` inside `.adt-search-ph`.

Optional site key:: `site.keys.askEnabled` — theme mirror if you wire a plain `#search-input` yourself. See ARCHITECTURE.

== Product shape (target)

* *One omnibox* — `/` and `?` set Search vs Ask mode on the **same** field (not two widgets).
* *Scope control* — dropdown *built into* the left edge of the field (*All docs* / *This component* / optional *This version*). Not multiple boxes by placement.
* *Compound UI* — one pill: `[ Scope ▾ | Search or Ask ]` (`.adt-search-compound` + `.adt-search-scope`); shared border, inner vertical rule, left/right rounding split across scope and input.
* *Default scope* — *Current component* on docs pages when detectable; *All* on home / when ambiguous (with a component list). See ARCHITECTURE.
* *Lunr-first* — keyword results while typing in Search mode; Ask only on explicit mode / submit. Optional debounced question-detection may come later; it is not the default.
* *Tier-0 local assist* (optional) — ultra-light on-device model for query rewrite / short answers over retrieved chunks; remote `backend_url` is an optional upgrade. Never put API keys in the playbook.
* *Upstream* — propose multi-value facet / filter API on lunr-extension; Valentus dropdown wraps store metadata first.
* *Layout* — compound control lives in the outer search band (outside the 3-col shell) so scope + results are not clipped.

Keyboard (when not typing in a field)::

* `/` — *Search* mode (lunr)
* `?` (Shift+/) — *Ask* mode on the same field

Hint badges show `/` and `?`. See ARCHITECTURE for the `key === '?'` vs `key === '/' && shiftKey` caveat.

Phase 1 stub may still show separate Search/Ask panels; compound scope markup/CSS may be visual-only until filters wire up. Product target is omnibox + conjoined scope.

== Theme integration

When the extension is *not* registered, Valentus may still render a plain `#search-input` with `placeholder="Search"`. The omnibox overlay lives in this package — prefer `{{> adt-search-chat}}` (nav-menu already does when `SITE_SEARCH_CHAT` is set) rather than re-implementing on the fallback field.
