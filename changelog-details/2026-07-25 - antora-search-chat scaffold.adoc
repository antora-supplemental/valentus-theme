= 2026-07-25 — antora-search-chat scaffold

== Summary

Phase 1 of a Valentus-owned Antora extension that **wraps** `@antora/lunr-extension` with Search / Ask (AI Q&A later). Lunr is not forked.

== Product decisions (documented)

* *One omnibox* — placeholder *Search or Ask* (fake overlay; native placeholder cannot style a dead *or Ask*); `/` and `?` set Search vs Ask mode on the same field (not two widgets).
* *Ask affordance* — when Ask is missing/disabled, keep the phrase but grey + strike *or Ask* (`.adt-search-ph-ask.is-disabled`). Enabled via `ask_enabled` or inferred from `backend_url` / `local_assist`.
* *Scope control* — one compound control: conjoined scope dropdown on the *left edge* of the field (`[ Scope ▾ | Search or Ask ]`). Not multiple boxes by placement.
* *Default scope* — *Current component* on docs pages when detectable; *All* on home / when ambiguous.
* *Upstream* — propose multi-value facet / filter API on lunr-extension; Valentus wraps store metadata first.
* *Layout* — compound control lives in the outer search band (outside 3-col) so scope/results are not clipped.
* *Lunr-first* — keyword results on keystrokes in Search mode; Ask only on explicit mode / submit. No speculative AI on every keystroke by default; optional debounced question-detection may come later.
* *Tier-0 local assist* (optional) — ultra-light on-device model for query rewrite / short answers over retrieved chunks; remote API via `backend_url` is an optional upgrade. No API keys in the playbook.

== Package

`packages/antora-search-chat`

* `ARCHITECTURE.adoc` — wrap vs fork, omnibox + compound scope (ASCII/mermaid), tiers, lunr + RAG data flow, config keys, privacy, phases
* `lib/index.js` — Antora extension; injects UI beside lunr; sets `SITE_SEARCH_CHAT`
* Stub Ask path + pluggable `backend_url` (no secrets; no LLM yet). Compound scope markup/CSS is a visual stub (not wired to lunr filters yet); tabbed Ask panels remain transitional.

== UI

Owns the left search slot in `.adt-tool-band` (`.adt-nav-search` / `.adt-tool-search`) via `adt-tool-band.hbs` when `SITE_SEARCH_CHAT` is set. Keeps `#search-input` for lunr. Transitional Search/Ask tabs are visually hidden in the tool band; `/` and `?` still switch modes.

Compound hooks:: `.adt-search-compound` wraps `.adt-search-scope` + `.adt-search-input-wrap` (`#search-input` + `.adt-search-ph` overlay; shared border, inner vertical rule, split rounding).

Keyboard:: `/` → Search mode (lexical); `?` (Shift+/) → Ask mode (same field when omnibox lands). Listener accepts `key === '?'` or `key === '/' && shiftKey`.

Theme note:: Plain `#search-input` fallback (no extension / no `SITE_SEARCH_CHAT`) still says `Search` only; overlay ships in this package. `adt-tool-band.hbs` prefers `{{> adt-search-chat}}` when the extension is registered.

Double-click select:: Antora UI default blocks multi-click selection inside `[data-panel=menu]`; tool-band search is outside that panel. This package still `stopPropagation`s multi-click `mousedown` on `#search-field` / Ask form for safety. Overlay uses `pointer-events: none`.

== Playbooks

Demo playbooks (`antora-playbook.yml`, local, visual-demo, ui-modules) register `./packages/antora-search-chat` after lunr. Ask defaults off (struck *or Ask*).
