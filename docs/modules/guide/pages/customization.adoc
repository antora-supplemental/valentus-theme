= Customization
:navtitle: Customization
:description: How to customize the Antora Dark Theme colors, toggle button, and more.

The dark theme is fully customizable.
This guide covers common customization scenarios.

== Changing Colors

Edit `supplemental-ui/css/site-extra.css` to customize the color palette.

IMPORTANT: Prefer putting layout-affecting rules into the UI bundle’s compiled `site.css` (or Valentus supplemental CSS that ships in the release zip) instead of a late extra `<link>`.
Layered stylesheets after Default UI `site.css` cause a refresh “settle” flash (FOUC).
Valentus currently ships an *interim* paint-hold in `partials/head-meta.hbs` (`html.adt-fouc-pending`) marked pending upstream Default UI guidance / !207 / !213 — if you override `head-meta.hbs`, keep that hold (stylesheets first, then preference scripts, then release only after `document.fonts` for your linked families — or you reintroduce CSS settle and webfont FOUT / width jump).

== Overriding `head-meta.hbs` (brand overlays)

Hubs often override `supplemental-ui/partials/head-meta.hbs` for fonts, favicons, or brand CSS.
**Copy the full Valentus CSS chain**, then add brand overlays only — do not replace the partial with a minimal dark-mode stub.

Required Valentus stylesheet links (order matters; match upstream `head-meta.hbs`):

. `site-extra.css`
. `site-doc-layout.css`
. `site-visual.css`
. `site-read-width.css`
. `site-font-size.css`
. `site-math.css` (when math is enabled)

Also keep: paint-hold (`adt-fouc-pending`), dark-mode / read-width / font-size FOUC preference scripts, and webfont `document.fonts` release.
After those, append **only** hub brand sheets (e.g. `brand.css`, `nav-typology.css`).
Dropping layout/visual sheets while keeping a brand overlay yields a broken mast/nav even though the site “builds”.

== Supplemental footer scripts (do not double-load)

Valentus `footer-scripts.hbs` already loads `site.js` and the theme’s footer scripts (dark mode, accordion, visual, read-width, font-size, math, …).

If your hub overrides `footer-content.hbs` or adds another footer partial, **do not** re-emit:

* `site.js` (id `site-script`)
* Valentus scripts already listed in theme `footer-scripts.hbs`

Double-loading `site.js` registers expand/collapse handlers twice and breaks nav tree expand.
Load **only** hub companions after the theme scripts (e.g. `site-nav-tree-current.js` after `site.js`). Prefer extending `footer-scripts.hbs` over stuffing script tags into `footer-content.hbs`.

== Mast version control (`~` / Default)

Helper `adt-version-mode` drives the breadcrumb version control (Valentus 2.0.19+):

| Mode | When | UI |
| --- | --- | --- |
| `hide` | Only the implicit/unversioned Antora version (`~`), or no version | Version control omitted (no “Default” chip) |
| `plain` | Exactly one **named** version | Underlined text (not a dropdown) |
| `menu` | Two or more versions | Dropdown; implicit rows still use the `adt-version-label` fallback **Default** |

**Rationale:** showing “Default” for a single unversioned component teaches little and clutters the mast; hiding matches reader expectation that unversioned docs have no version picker.

**Possible future option (not shipped):** show a literal unclickable `~` for Antora pedagogy instead of hiding. Do not invent a conflicting hub override that re-labels `~` as “Default” when the theme already hides it.

=== Example: Change Link Color

To change the link color to green:

[source,css]
----
html.dark-theme a {
  color: #51cf66;
}

html.dark-theme a:hover {
  color: #8ce99a;
}
----

== Adding Custom Styles

To style additional elements not covered by the default theme, add new selectors prefixed with `html.dark-theme`:

[source,css]
----
html.dark-theme .my-custom-element {
  background-color: #25262b;
  color: #c1c2c5;
}
----

== Toggle Button Position

By default, the toggle button is inserted at the beginning of `.navbar-end`.

To change its position, modify the `ensureToggleButton()` function in `site-dark-mode.js`:

[source,javascript]
----
// Insert at the end instead of the beginning
navbarEnd.appendChild(button);
----

== Custom Toggle Button

If you want to use your own toggle button markup, add an element with `id="theme-toggle"` anywhere in your page:

[source,html]
----
<button id="theme-toggle" aria-label="Toggle dark mode">
  🌙
</button>
----

The script will detect it and attach the click handler automatically instead of creating its own button.

== Disable System Preference Detection

To always start in light mode regardless of system preference, modify the inline script in `head-meta.hbs`:

[source,handlebars]
----
<script>
(function () {
  const themeKey = 'antora-theme';
  const savedTheme = localStorage.getItem(themeKey);
  // Only apply dark mode if explicitly saved
  if (savedTheme === 'dark') {
    document.documentElement.classList.add('dark-theme');
  }
})();
</script>
----

== CSS Custom Properties

While the current theme uses explicit color values, you can refactor to use CSS custom properties for easier theming:

[source,css]
----
html.dark-theme {
  --dt-bg-primary: #1a1b1e;
  --dt-bg-elevated: #25262b;
  --dt-text-primary: #c1c2c5;
  --dt-text-heading: #ffffff;
  --dt-link: #4dabf7;
  --dt-border: #373a40;
}

html.dark-theme body {
  background-color: var(--dt-bg-primary);
  color: var(--dt-text-primary);
}
----

This makes it easier to create multiple dark theme variants.

== Side-rail panel wash (nav + sidebar TOC)

Light mode defaults to a clean flat rail (`--adt-side-panel-bg: transparent`).
Dark mode uses a subtle elevated wash by default.

To enable the panel treatment in light mode (or force it), add one of:

* class `adt-side-panels` on `html` or `body`
* attribute `data-adt-side-panels="true"` on `html`

Tokens: `--adt-side-panel-bg`, `--adt-side-panel-radius` (default `2px`), `--adt-side-panel-pad`.

Sidebar TOC **CONTENTS** always gets a little padding + radius so the label is not flush to the edge.
In-doc Asciidoctor `:toc:` (`.doc .toc` / `#toc`) is styled separately as a muted block — it is **not** part of `@antora-supplemental/page-context` metadata.

== VCS Repo Logo (Download button replacement)

The theme replaces the default UI's nonfunctional "Download" button with a version control provider logo that links to the docs repository.
Provider is detected by domain (GitHub, GitLab, Bitbucket, Gitea, Codeberg, Forgejo, SourceHut); you can change or add logos by replacing or adding SVGs under `supplemental-ui/img/vcs/`.
See xref:vcs-repo-logo.adoc[VCS Repo Logo] for detection rules and how to customize or hide the logo.
